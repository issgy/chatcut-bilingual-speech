# B-roll、交付与清理

## 素材选择与编排

- 使用本次用户提供或配置的 Google Drive 素材根文件夹（`broll_library.folder_url_or_id`）。通过当前账号解析并验证实际文件夹 ID；不得使用作者或其他用户的素材库。
- 只依据子文件夹名称选择与主题相符的分类，如城市夜景、城市雨夹雪、孤独、伤感、雨夜城市街道、治愈；不得对候选素材抽帧、看缩略图或分析画面内容来选材。允许读取文件名、类型、时长等技术信息。最终合成核验用于检查排版、黑帧、覆盖和转场，不能借机按画面内容重新筛选。
- 列出所选分类的全部可用视频文件后随机无放回抽取，保存候选文件 ID 与本次抽取结果。仅下载最终实际抽中的文件，禁止预下载整个分类。不得修改或删除云端原始素材。
- 每条至少 3 个不同文件；B-roll 区间确实很短时可以降至 2 个，并在最终审核中说明原因。每条内部不重复，两条之间按 Drive 文件 ID 全局去重。舍弃一条后剩余视频仍使用多个文件。
- 素材不足时先从其他适合的分类补足；仍不足则报告缺口，不静默重复。只有用户明确同意才可例外重复。不得为补足数量自动下载其他来源。
- 从用户确认的切入点开始覆盖所需区间。所有 B-roll 静音，文件之间统一叠化；转场须在 ChatCut 实际可支持的轨道/效果模型中实现并核验。
- 保留已确认 A-roll 演讲音频，不能改变其时长、语速、内容或加入素材原声、背景音乐。叠化仅影响画面，不改变总时长。
- 字幕位于 B-roll 上方，维持已确认的样式和同步。
- 每个使用文件记录：Drive 文件 ID、来源文件名、分类/父文件夹 ID、本地路径、素材起止时间、成片时间轴起止时间、转场时长。记录所有实际使用区间。

## 导出与飞书交付

最终成片确认后执行，不额外索取一次导出或上传确认：

1. 用 ChatCut 导出 MP4，H.264、1920×1080、30fps。遵循当前 ChatCut 工具的导出说明并追踪真实完成状态。
2. 核验成品编码、尺寸、帧率、时长与音轨；确认原演讲声保留、无背景音乐、无 B-roll 原声。仅检测有音轨不能证明混音正确，应结合轨道状态和听检。导出设置或结果不满足时不能声称符合要求。
3. 使用本次用户指定的飞书交付文件夹（`delivery.folder_url_or_token`），解析并验证真实文件夹 token。用户只提供名称时先查找，同名结果依据路径消歧；无法唯一确定或目标不可写时报告阻塞，不猜目标，也不上传到其他文件夹。
4. 上传每条保留视频的最终 MP4，保存返回的文件 token、名称和访问链接。
5. 上传后重新查询目标文件夹确认文件存在，并通过文件元数据/下载读取核验当前账号确实能访问；可得时比对文件大小或校验和。不能仅以“上传接口成功”或构造 URL 当作核验。
6. 两条均保留时须全部上传且核验成功才清理共用源视频。部分失败保留所有仍需要的文件，报告哪些成功、哪些待重试。

## 本地清理

仅当配置 `cleanup.move_task_temporary_files_to_trash` 为 true，且本次交付全部上传成功并完成访问核验之后，将本次独立目录与登记清单中符合条件的文件移入系统废纸篓：下载的源视频、实际使用的 B-roll、ChatCut 导出缓存、浏览器下载副本及本次其他临时文件。

- 使用系统可恢复的移入废纸篓方式；不永久删除，不使用 `rm` 代替。无法移入废纸篓时保留文件并报告。
- 严格匹配本次登记的绝对路径；不按宽泛通配符清理下载目录、共享缓存、其他任务文件或用户原有素材。
- 确保清理不破坏仍依赖本地文件的 ChatCut 项目；先核验导入素材在项目端可用。无法证明安全时保留相关本地文件并报告原因。
- 不删除 ChatCut 云端项目、Google Drive 原始素材或 YouTube 原始内容。
- 保留轻量任务状态、主题地图、字幕数据、素材来源清单及飞书交付凭据，以便追溯；它们不属于待清理的临时媒体。
